# 장애 보고서: 로그 디스크 고갈로 인한 재고 서비스 장애 (2025-06-21)

## 요약
2025-06-21 03:11 ~ 05:40 동안 재고 스냅샷 저장과 재고 조회 API가 실패했다.
원인은 디버그 로깅 레벨이 프로덕션에 적용된 채 방치되어 로그가 평소의 40배로
쌓였고, /var/log 볼륨이 가득 차 "No space left on device" 쓰기 실패가 발생한 것이다.

## 영향
- 재고 조회 API 오류율 최대 67%, 야간 배치 3건 실패
- 로그 유실로 장애 초기 30분의 분석 데이터 결손

## 타임라인 (KST)
- 06-19 18:00 디버깅 목적으로 로그 레벨 DEBUG 변경 (원복 누락)
- 03:11 disk usage 90% 경고 (알람 미설정으로 미인지)
- 03:37 No space left on device 최초 발생, 스냅샷 저장 실패
- 04:55 온콜 엔지니어 수동 인지
- 05:20 로그 정리 및 로테이션 강제 실행
- 05:40 정상화

## 근본 원인
임시 디버깅 설정(DEBUG 레벨)이 원복되지 않은 채 이틀간 방치되어 로그 볼륨이
평소 대비 40배로 증가했다. 디스크 사용률 알람이 없어 임계 초과를 인지하지 못했고,
결국 디스크가 가득 차 쓰기 계열 작업 전체가 실패했다.

## 5 Whys
1. 왜 재고 API가 실패했나? — 스냅샷/상태 파일 쓰기가 IOException(disk full)으로 실패했다.
2. 왜 디스크가 가득 찼나? — 로그 파일이 이틀간 평소의 40배 속도로 누적되었다.
3. 왜 로그가 폭증했나? — 디버깅용 DEBUG 레벨 설정이 프로덕션에 남아 있었다.
4. 왜 원복이 누락됐나? — 임시 설정 변경에 만료 시간/추적 절차가 없었다.
5. 왜 조기 인지가 안 됐나? — 디스크 사용률 임계 알람이 설정되어 있지 않았다.

## 재발 방지 대책
- [완료] 전 서비스 디스크 사용률 80/90% 단계 알람 추가
- [완료] 로그 로테이션 정책 표준화 (size 기반 + 보존 7일)
- [진행] 임시 설정 변경 자동 만료(TTL) 도구 도입
- [진행] 로그 레벨 변경을 배포 이력에 기록해 감사 가능하게 개선
