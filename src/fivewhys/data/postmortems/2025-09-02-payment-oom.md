# 장애 보고서: 결제 서비스 반복 OOM 재시작 (2025-09-02)

## 요약
2025-09-02 14:20 ~ 16:05 동안 결제 승인 API가 간헐적으로 실패했다(오류율 최대 41%).
원인은 신규 기능의 이미지 처리 코드가 대용량 객체를 캐시에 무한 축적한 메모리 누수로,
JVM heap 고갈 → OutOfMemoryError → 컨테이너 OOMKiller 재시작이 반복되었다.

## 영향
- 결제 승인 실패 및 재시도 폭증, 중복 결제 문의 37건
- payment-service 컨테이너 총 11회 재시작 (exit code 137)

## 타임라인 (KST)

- 14:20 GC pause 급증, old gen 사용률 90% 초과 (WARN)
- 14:41 java.lang.OutOfMemoryError: Java heap space 최초 발생
- 14:44 OOMKiller에 의한 첫 컨테이너 재시작 (exit code 137)

## 근본 원인
이미지 리사이즈 결과를 무제한 인메모리 캐시에 저장하는 코드가 배포되어
힙 메모리가 지속 증가했다. 힙 고갈 시 GC pause가 급증하며 처리 지연이 발생했고,
최종적으로 OutOfMemoryError와 OOMKiller 종료가 반복되었다.

## 5 Whys
1. 왜 결제가 실패했나? — payment-service가 응답 중 connection reset으로 끊겼다.
2. 왜 연결이 끊겼나? — 컨테이너가 OOMKiller에 의해 반복 종료되었다 (exit code 137).
3. 왜 메모리가 고갈됐나? — 이미지 캐시가 상한 없이 힙에 누적되었다.
4. 왜 상한 없는 캐시가 배포됐나? — 부하 테스트에 장시간 메모리 시나리오가 없었다.
5. 왜 테스트 공백이 있었나? — 메모리 회귀는 릴리즈 체크리스트 항목이 아니었다.
