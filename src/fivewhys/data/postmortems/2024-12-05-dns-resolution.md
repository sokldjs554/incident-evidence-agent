# 장애 보고서: 내부 DNS 캐시 오염으로 인한 간헐 타임아웃 (2024-12-05)

## 요약
2024-12-05 16:40 ~ 18:10 동안 서비스 간 호출이 간헐적으로 실패했다(오류율 7~15%).
내부 DNS 리졸버의 캐시가 스케일다운된 노드의 IP를 TTL 초과 후에도 계속 반환해,
존재하지 않는 인스턴스로의 연결 시도가 타임아웃되었다.

## 영향
- 서비스 간 호출 간헐 실패 (connection timeout), 재시도로 지연 증가
- 간헐성 때문에 원인 특정까지 55분 소요

## 타임라인 (KST)
- 16:30 payment-service 오토스케일 다운 (노드 4 → 2)
- 16:40 간헐적 connection timeout 발생 시작
- 17:20 특정 IP 대상 연결만 실패하는 패턴 확인
- 17:35 DNS 리졸버 캐시에서 회수된 IP 잔존 확인
- 17:50 리졸버 캐시 플러시, negative TTL 설정 수정
- 18:10 오류율 정상화

## 근본 원인
커스텀 DNS 리졸버 설정의 max-cache-ttl이 서비스 디스커버리 TTL보다 길어,
이미 회수된 노드 IP가 캐시에 잔존했다. 간헐 실패는 라운드로빈으로 죽은 IP가
선택될 때만 발생해 패턴 파악이 어려웠다.

## 5 Whys
1. 왜 호출이 간헐적으로 실패했나? — 일부 요청이 존재하지 않는 IP로 라우팅되었다.
2. 왜 죽은 IP로 라우팅됐나? — DNS 캐시가 회수된 노드의 IP를 계속 반환했다.
3. 왜 캐시가 갱신되지 않았나? — 리졸버 max-cache-ttl이 디스커버리 TTL을 무시했다.
4. 왜 설정 불일치가 있었나? — 리졸버 설정 변경 시 디스커버리 팀 리뷰가 없었다.
5. 왜 원인 특정이 늦었나? — 서비스 간 호출 실패를 대상 IP 기준으로 집계하는 뷰가 없었다.

## 재발 방지 대책
- [완료] 리졸버 TTL 설정을 디스커버리 TTL 이하로 강제
- [완료] 대상 IP 차원의 호출 실패 대시보드 추가
- [진행] DNS 설정 변경에 크로스팀 리뷰 필수화
