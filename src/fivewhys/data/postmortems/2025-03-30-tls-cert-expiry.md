# 장애 보고서: TLS 인증서 만료로 인한 로그인 전면 장애 (2025-03-30)

## 요약
2025-03-30 09:00 ~ 10:22 동안 전체 로그인이 실패했다. 사내 인증 게이트웨이의
TLS certificate가 만료되어 user-service의 SSL handshake가 전부 실패했고,
신규 토큰 발급이 불가능해졌다.

## 영향
- 신규 로그인 성공률 0% (기존 세션은 유지)
- 고객센터 문의 210건, 앱스토어 리뷰 평점 일시 하락

## 타임라인 (KST)
- 09:00 인증서 만료 시각 도래 (notAfter 초과)
- 09:01 user-service SSL handshake failed / certificate expired 급증
- 09:07 api-gateway 로그인 요청 401 연쇄
- 09:40 만료 인증서 확인, 갱신 절차 시작
- 10:15 신규 인증서 배포 완료
- 10:22 로그인 성공률 정상화

## 근본 원인
인증 게이트웨이의 TLS 인증서가 만료되었다. 인증서 만료일을 추적하는 대시보드는
있었으나 알람이 연결되어 있지 않았고, 갱신 담당이 퇴사하며 수동 갱신 절차가
인수인계에서 누락되었다.

## 5 Whys
1. 왜 로그인이 실패했나? — user-service가 인증 게이트웨이와의 SSL handshake에 실패했다.
2. 왜 핸드셰이크가 실패했나? — 서버 certificate가 expired 상태였다.
3. 왜 만료 전에 갱신되지 않았나? — 수동 갱신 절차의 담당자가 부재했다.
4. 왜 만료가 사전에 감지되지 않았나? — 만료일 대시보드에 알람이 연결되어 있지 않았다.
5. 왜 자동 갱신이 아니었나? — 레거시 장비가 ACME 자동 갱신을 지원하지 않아 방치되었다.

## 재발 방지 대책
- [완료] 인증서 만료 D-30/D-14/D-7 알람 추가 (온콜 채널 연동)
- [완료] 전사 인증서 인벤토리 구축 (만료일·담당·갱신 방법)
- [진행] ACME(cert-manager) 기반 자동 갱신으로 단계적 전환
- [진행] TLS 핸드셰이크 실패율 서비스별 대시보드 추가
